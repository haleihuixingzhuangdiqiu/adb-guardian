# ADB 守护

给固定放置的 Android 测试机使用的本地工具。Android 11 及以上；当前构建目标 Android 16。手机 App 尝试恢复系统无线调试开关，并提供可选的 CPU 与屏幕保持；电脑伴随工具发现变化后的连接端口并重连已登记设备。

这是免 root 的尽力恢复方案，需要一次性授权。保留 Android 的网络信任、电脑配对和 TLS；不开放明文 5555，不读取配对码、ADB 私钥、账号或其他 App 数据。App 未声明联网权限，没有云端服务。

## 首次配置

1. 安装交付的 `ADB-Guardian-0.2.0.apk`。这是本地 debug 签名测试版，保留此项目与本机签名，便于后续覆盖更新。
2. 手机和电脑接入可互通的局域网。在系统开发者选项中打开无线调试，允许当前网络并勾选“始终允许”。
3. 用 Android Studio 的 Wi-Fi 配对，或运行 `adb pair IP:配对端口`，按终端提示输入手机显示的验证码。配对端口不是连接端口；不要把验证码写进脚本或聊天。
4. 用 `adb devices -l` 找到目标手机的完整标识，执行下方激活命令。已经无线连上的手机不需要 USB；也可用同一根 USB 数据线逐台完成授权。标识含空格时必须保留引号。

```bash
python3 desktop/adb_guardian.py activate --serial "DEVICE_SERIAL"
```

激活只给指定设备中本 App 授予 `android.permission.WRITE_SECURE_SETTINGS`，并在 `~/.config/adb-guardian/devices.json` 登记公开设备标识。若系统拒绝授权，会明确报错，不代表已成功。也可手动授权：

```bash
adb -s "DEVICE_SERIAL" shell pm grant dev.local.adbguardian android.permission.WRITE_SECURE_SETTINGS
```

5. 回到手机 App，允许通知并点“开始守护”。iQOO / vivo 需检查系统是否允许本 App 自启动、后台运行；具体入口依 OriginOS 版本而异。小米使用屏幕保持时，需另外打开“防止自动熄屏（允许变暗）”和独立的“兼容悬浮状态条”，进入系统悬浮窗设置授权，再返回应用；请保留可见状态条。
6. 每台手机分别激活一次，然后启动电脑守护：

```bash
python3 desktop/adb_guardian.py watch
```

macOS 如需退出终端后继续运行、登录后自动启动，显式执行：

```bash
python3 desktop/macos_service.py install
python3 desktop/macos_service.py status
# 停止电脑守护并取消其自启动（保留配置、日志和手机设置）：
python3 desktop/macos_service.py remove
```

安装器把脚本复制到 `~/Library/Application Support/ADBGuardian/`，只安装当前用户的 `dev.local.adbguardian.watch` LaunchAgent，不修改系统 ADB 设置。日志位于 `~/Library/Logs/ADBGuardian/guardian.log`，单份最多 512 KiB，保留两份历史。电脑需要保持唤醒；电脑睡眠期间不能维持连接，唤醒后继续。此项目不会自动替用户安装该服务。

所有电脑命令都支持 `--adb /绝对路径/adb`；`activate`、`watch` 和 macOS 安装器均支持 `--config /绝对路径/devices.json`。同一批设备使用同一套配置和同一用户的 ADB 授权。

## 行为与边界

- App 目标检查间隔为 30 秒；Android 调度和厂商限制可能延迟。服务带持续通知和停止入口，只有用户启用后才尝试开机恢复。
- 系统拒绝恢复或回写关闭时，暂停自动写入并显示“需要确认系统设置”。处理系统确认后点“确认后重试”，不会反复点击或绕过信任确认。
- “守护运行中”只表示本地守护运行、无线调试开关已开启。没有声称电脑在线、端口可达或测试会话完整。
- “充电时加强保活”只在守护有条件运行且接电时持有有超时的 CPU 唤醒锁，屏幕可以熄灭。拔下充电器或停止守护时释放；会影响功耗/温度，不适合电池和后台行为测试。
- “防止自动熄屏（允许变暗）”是独立选项，默认关闭，升级不改变原守护/CPU 选项。仅守护就绪、屏幕处于交互状态、系统支持且电池/热状态符合条件时申请。修改选项不会启动已停止的守护；打开页面也不会重置选项。界面与通知独立显示屏幕保持状态，所有机型均用“已请求”表示已向系统申请，不证明实际生效；`isHeld()` 也不能证明厂商允许锁的效果。小米未使用兼容状态条时明确提示后台可能受系统限制。
- “兼容悬浮状态条”是另一个独立偏好，默认关闭，任意机型均可手动开启。点“打开系统悬浮窗授权设置”，在系统中允许本应用显示在其他应用上层，再返回应用；授权入口也可用于撤销。需同时启用守护、屏幕保持与此偏好，且已实际解锁、策略允许并有悬浮权限，才显示侧边中央的可读小条“ADB·屏幕保持”。它静态显示，不抢焦点、不响应触摸、不设置常亮、亮度或唤醒标志；Android 12+ 将窗口不透明度限制在系统触摸穿透阈值内，维持可读性，仍可能受厂商触摸策略限制。申请后显示“已请求·请保留状态条”。仅改变兼容偏好不会启动已停止的守护，也不会打开屏幕保持。
- 小米框架已观察到对无可见窗口 App UID 的后台 DIM 锁限制，屏幕保持需独立启用兼容悬浮状态条并授予悬浮权限。**本次小米实测已通过自然 DIM**：实际无操作 725.178 秒（12 分 05 秒）后，屏幕仍为 ON/DIM，状态条真实可见，目标屏幕锁无 `DISABLED`；沿用原 10 分钟熄屏时间、手动亮度值 128 与手动模式。该结果限于本次设备和条件，不保证其他机型或系统版本；系统可能隐藏悬浮窗，窗口添加成功本身仍不代表屏幕保持成功。缺权限或窗口添加失败会释放屏幕锁并显示暂停/限制，不继续宣称已请求成功；Wi-Fi 调试守护仍独立运行。关闭屏幕保持、停止/销毁服务、保护暂停、关屏、兼容模式锁屏等待或撤权检查都会释放屏幕锁并移除窗口；关闭屏幕保持仍保留兼容偏好。移除失败会记录错误并提示检查，保留引用供后续清理重试。
- 兼容模式通过 `KeyguardManager` 同时检查锁屏与设备锁定，不覆盖锁屏；收到实际解锁事件后重新评估，不主动唤醒。撤销悬浮权限时 Android 可能直接结束 App 进程，由系统回收窗口与锁；进程仍运行时，在现有目标 30 秒检查或应用 `onResume` 时处理，系统调度可能延迟。回到应用仅通知现存服务重新检查，不启动已停止的服务。
- 屏幕保持使用独立的 `SCREEN_DIM_WAKE_LOCK`，允许系统正常变暗及自动亮度，不修改亮度、熄屏超时或系统常亮设置。按电源键关屏由系统处理，不主动唤醒；再次实际亮屏后才检查恢复。每轮检查续期 90 秒超时，关闭选项、停止或销毁服务会释放，进程死亡后由系统回收。超时回调在应用进程执行，进程冻结时不能保证按时释放；它不是系统级故障兜底。厂商对已弃用锁级别的支持和变暗行为仍须实际验证，不支持或调用失败会明确显示。
- 屏幕保持的保守策略：电量≤20%、电池温度≥40℃或系统热状态≥中度（2）即暂停；启用及恢复须同时满足电量≥25%、电池≤38℃、热状态≤轻度（1）。任一数据未知也暂停；电量和温度只读取，真实电池状态保持不变，不模拟充电、不覆盖电池状态，接电不豁免阈值。这是减少消耗的产品策略，不保证零损耗或硬件安全；长期亮屏仍耗电并可能增加屏幕磨损，请按需开启。
- 停止守护取消自动恢复，保留现有无线调试设置；如需关闭 ADB，请再从系统无线调试中关闭开关。强行停止 App 后通常要手动重新打开；普通开机广播不保证首次解锁前运行。
- 电脑只操作登记设备，区分连接与配对端口，每次通过 shell 校验真实序列号。mDNS 名称碰撞的 `(2)` 后缀可识别。设备独立退避，不全局 kill-server、不自动重启手机。失效配对需要人工恢复。
- 瞬断仍会中断 shell、安装或测试；本工具不自动重放业务操作，不重建调用方自己的 forward/reverse。
- iQOO / vivo 的 WRITE_SECURE_SETTINGS、隐藏设置键、后台限制和长期稳定性必须实机确认。即使界面开关为开，也可能有网络隔离、端口监听或授权问题；不能据此宣称“永不断线”。

## 开发与验证

独立于 ICard，无业务接口、登录流程或发布上传。Gradle 构建必须使用本机资源预算入口：

```bash
env JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home' \
  /Users/lgj/.codex/scripts/with-gradle-budget.sh -- \
  ./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug --offline --max-workers=4
python3 -m unittest discover -s desktop -t .
```

APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。验证原始证据保存在忽略的 `build/mobile-regression/`；不将真实设备配置、密钥或原始日志提交。Maestro 用例不使用默认 `launchApp`，因为它会自动授予开发权限，导致权限边界测试失真。运行前通过 ADB 启动本 App，并明确准备对应权限/系统确认前置状态。

0.2.0 已有构建、lint、18 项单元测试通过，最终两条文案资源修改后再组装通过。源码最终审查未发现新增阻塞。本轮交付准备只更新文档与打包现有 APK，未重新构建或操作设备。

小米自然 DIM 在实际无操作 725.178 秒后通过；手动关屏超过 200 秒未被唤醒，屏幕保持窗口与屏幕锁均已清理，守护及两个偏好仍保留。两项实测均沿用 10 分钟熄屏、手动亮度值 128 与原亮度模式，未模拟充电、未覆盖电池状态。原始证据保留在本地忽略的 `build/screen-regression/`，不随交付包分发。

- 新增悬浮窗口存在时的进程死亡清理（旧用例未覆盖新增窗口）。
- 仅关闭兼容偏好时移除窗口，且不改变守护及屏幕保持总开关。

### 0.2.1 vivo 后台屏幕保持（versionCode 3）

0.2.1 修复本次两台 vivo V2055A 在后台仍按超时自动关屏的问题。上方 0.2.0 的交付记录、APK 哈希与小米实测属于原版本。其他型号及系统仍需验证，不能把申请成功当作实际保持成功。

仅 `Build.MANUFACTURER` 为 vivo（不区分大小写）且用户开启“兼容悬浮状态条”时，在既有检查中尝试单独的 `SCREEN_DIM_WAKE_LOCK | ON_AFTER_RELEASE`：同步 acquire 后立即在 finally 中 release，不跨回调持有。原普通 DIM 锁仍不带 `ON_AFTER_RELEASE`；小米及其他厂商保持原路径。复用屏幕保护策略的 ACTIVE 判定，并在申请前复查守护运行/就绪、屏幕保持与兼容选项、interactive、实际解锁、悬浮权限及窗口仍附着可见。窗口状态检查不代表 OEM 实际允许保屏，效果仍需实测。

使用 `elapsedRealtime` 单调时钟将尝试限制为最多每 30 秒一次，初次允许可立即尝试；电池、热状态和 Activity 的密集回调不增加频率，暂停或切换选项不重置限频。停止、关闭选项、关屏、保护或未知安全数据时不新增 pulse；释放路径不补 pulse。不新增后台循环、闹钟、CPU 锁或权限，不改亮度、原系统熄屏超时（本次设备为 600000 ms），不模拟电池或充电。

**停止残留：停止/保护暂停会停止主动续时并释放锁，不能承诺立即息屏。** 已核验的 vivo framework 对普通 DIM 锁的释放也可能续时，所以应从最后一次有效 release（可能就是停止时）计算，而不是最后一次 pulse。在没有新交互、其他保屏来源且原超时为 10 分钟的条件下，DIM 仍可能继续约 10 分钟。普通进程死亡也不等于停止：服务沿用 `START_STICKY`，系统重启后若仍满足条件，可能继续申请。长期亮屏仍有耗电和屏幕损耗。

本次两台 V2055A（Android 13 / 14）均已覆盖升级并保留数据；实际连续无交互分别达到 750.199 秒、746.857 秒，仍为 ON/DIM，亮度未周期性回升。沿用原 600000 ms 熄屏时间、手动亮度值 255 和手动模式，电池保持真实更新。两台模拟电源键关屏后持续观察约 79 秒，均保持 OFF，屏幕锁与浮层已移除，无后续续时；主动亮屏后可恢复。正常停止（Android 14）与强制结束进程（Android 13）分别验证通过：锁已清除、无继续续时，约 603 / 604 秒后因原超时自然息屏。强制结束阻止了 sticky 自动重启；此项不等同于普通 kill 后的系统自动重启测试，也未专门命中瞬时 pulse 持锁窗口。两台验收后恢复为守护开启。
